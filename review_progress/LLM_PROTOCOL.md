# LLM operating protocol — active comprehensive review v2

Authority: explicit current learner instructions first, then this active workflow for comprehensive review, then historical preferences. This overrides conflicting older repository rules only while this plan is active. Do not change ChatGPT platform settings; these are repository instructions.

## Startup and routing
1. Verify main HEAD and read review_progress/index.json, its day_plan, active_batch (if non-null), order.json, this protocol, and the plan. Read relevant curriculum and dated evidence. Do not require the 4 MB legacy progress.json on ordinary review turns. Its stale status is known; only read it for historical reconciliation. For history use dated logs and sync_pending; never silently discard them.
2. If user only opens the repo or asks progress, show status without writing; offer resume. If user requests continuation/start while a batch is pending, show only remaining original prompts with same IDs; never regenerate, reveal answers or increment counters. If user submits numbered answers, route directly to active batch. If user asks a word meaning, answer as a side question, do not add new material or lose checkpoint. Explicit pause preserves all pending items.
3. Use actual Europe/Berlin date. On rollover preserve unfinished prior batch at its original path, record carryover, resume those IDs before new work. Never silently mark a day complete or create a second Markdown day file. A new study day starts only when actual study begins.

## Selection and study loop
- Freeze new entries until learner explicitly lifts freeze; the old progression-first and new-vocabulary rules are suspended. Daily first-pass quotas 30 verbs and 40 vocabulary, seven days/week; extra due retests, one grammar topic and five translation sentences. 16 study days is coverage estimate only. Use immutable order.json and stable IDs, excluding already issued first-pass targets even if paused. No new selection until pending batch graded or explicitly paused.
- Use batches of 10 by default (up to 20 on request). Before displaying, save exact Arabic prompts, target ID, accepted reference, dimensions, kind (first_pass/retest/grammar/context), session and status. Keep answers hidden. Clarify ambiguity in prompts using context without giving target. If an already issued prompt is ambiguous accept valid synonyms and record canonical target not recalled, then retest with clearer prompt.
- For verbs ask infinitive and complete Perfekt separately. Ignore parenthetical user-form annotations in canonical lemma. For nouns ask article and plural; separate lexical, article and plural scores. For other words request registered form/meaning. Accept valid alternatives; do not confuse spelling or grammar with semantic recall. No multiple choice unless explicitly requested.
- On answer: load latest batch and map numbered answers to exact exercise IDs. Save original raw text, dimension results (correct, partial, incorrect, not_answered, correct_with_support, valid_alternative), correction, hint status, dates, and due retests. A blank or omitted item stays pending unless explicitly skipped; "مش فاكر" is attempted incorrect. Partial submissions leave remaining prompts pending; do not grade twice. Preserve earlier attempts; corrections to grading append an audit note. Explain in simple Egyptian Arabic with natural German examples and translations; show short score summary and the next batch only after verified save and if learner wants to continue.
- Coverage is unique graded first-pass IDs, not correct count or issued count. Track infinitive/Perfekt separately; distinguish attempted from independently correct. Review status untested, weak, practicing, secure is scoped to dimension; require independent successes across spaced sessions before secure (at least two on separate dates, including delayed retest), never promote from copied correction. Contextual grammar and oral skills require separate evidence.
- Schedule misses after 1, 3, 7, 14, 30 days (adjust after repeated errors; restart interval sequence after failure). On new study session read earlier batch files for due retests; prioritize overdue weak items, then fill first-pass quota. Retest events get new IDs referencing original item; never count as new coverage. If workload too high carry unfinished work forward without claiming completion.
- Grammar: use complete curriculum headings to maintain explicit topic coverage, choose next unreviewed or weak topic, explain in Arabic and test five full sentences; record rule, original answers, errors, corrections, and separate context evidence. Use only existing vocabulary. Do not claim grammar complete based on broad topic list alone.

## Persistence and recovery
- Root progress.json remains immutable legacy archive; no rewrite. Use small index, per-day plan and per-batch JSON files. Store new grammar/context/retest evidence in separate batches. Keep files below 50 KB; partition as necessary. Update index pointers and counts only from actual graded evidence. Record day log summary, not duplicated full answer corpus. New session/plan edits and batch changes should commit atomically.
- Before write read current branch HEAD and affected files; build minimal diff; validate JSON, ID uniqueness, exact membership, references, counts, state transitions, and preserve existing raw answers. Use Git tree/commit/ref with expected head where available; on conflict re-read and merge, never overwrite newer progress. Re-fetch remote changed files before claiming saved. If write fails, clearly state unsaved, retain exact proposed changes in conversation, do not issue a replacement batch or count success.
- Run scripts/validate_review_progress.py when runtime checkout available; otherwise perform equivalent relevant checks on remote data and disclose Python not run. Legacy validator remains for historical migration, not a blocking condition for v2. Never claim reconciliation completed until verified.
